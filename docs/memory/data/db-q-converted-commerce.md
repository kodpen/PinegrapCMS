## Which commerce files are converted, and what stayed raw?
- `includes/fn/ecommerce.php` and `shopping_cart.php` (PR #2254): 100 and 36 calls with values (cart lines, ship-tos, zones, taxes, offers, inventory and reservation checks, recurring commissions, `duplicate_product()`), `(string)` where the SQL quoted, also where a value was written unescaped into quotes (now escaped), `(int)` for the bare `$discounted_by_offer` and the zone copy of `duplicate_product()`. Optional SQL pieces carry their values beside them: the restored price of `apply_offers_to_cart()` (`$values`), the affiliate code of the cart's offer code update (`$affiliate_code_values`, `array_merge()`). Raw stay the calls without values, the offer code lookup completed by `$sql_scope` and the products INSERT of `duplicate_product()`. `tests/db_q_ecommerce_cart_test.php` guards both and counts each literal value list against its `?`.
- `submit_order.php` and `includes/fn/forms.php` (PR #2272): 67 and 20 calls with values (order completion, gift cards, commissions, reservations, memberships, the 3-D Secure state rows, `log_activity()`, tax zones, login regions), `(string)` where the SQL quoted, `(int)` for the bare reservation quantity. The 3-D Secure rows passed `mysqli_real_escape_string()` values: the value goes in bare, so it is escaped once. Raw stay the billing contact update (`$sql_fax`, `$sql_tax`), the order update (`$sql_erp_on_account`, `$sql_credit_debit_card_values`), the visitor update that adds a bare `$total`, and in `forms.php` the clauses `$sql_where`, `$sql_collection`, `$sql_update` (its `$where` and `$form_type_filter` clauses moved to `db_q()` in PR #2296, `db-q-converted-access.md`). `tests/db_q_submit_order_forms_test.php` guards both.
- Express order and checkout steps (PR #2285): `express_order.php` 25, `get_express_order.php` 16, `get_shipping_method.php` 14, `billing_information.php` 11, `shipping_address_and_arrival.php` 9 calls with values. The offer code update carries `$affiliate_code_values` as in `shopping_cart.php`; the zone checks bind the bare shipping method id as `(int)`; the posted `ship_to_id` / `page_id` keep their `is_string()` guard inside the bound value. Raw stay the clauses `$sql_offline_payment_allowed`, `$sql_fax`, `$sql_tax`, `$sql_zones`, `$sql_address_type`, the bare column names (`$address_type`, `$street_address_or_po_box`) and the bare `$ship_to_id` / `$contact_id` of `get_express_order.php` (`$contact_id` may be `''`; `(int)` would turn that failing query into `id = 0`). `tests/db_q_express_checkout_test.php` guards them.

## What do their tests check beyond the content files' tests?
- Each literal value list of a `db_q()` call has as many elements as the '?' in the SQL string literals (a PHP ternary or `??` counts none), so a dropped or extra value fails the test.
