## How does a panel screen draw a code field?
- `pg_code_editor_attach(array('id' => 'code', 'code_type' => 'css', 'readonly' => false))` (`includes/fn/editor.php`) after the textarea: the facade's editor (`assets/js/pg_code_editor.js`, CodeMirror 6) takes the textarea's place and keeps its value current, so the form submits as before and the save path does not change. `code_type` takes the names `get_codemirror_javascript()` took (`mixed`, `css`, `javascript`, `application/json`, `php`, `xml`, …); `pg_code_editor_language()` maps them to the four grammars (`css`, `javascript`, `json`, else `html`). Optional `height`; without it the editor grows with the text up to 80vh and scrolls inside.
- The helper prints `pg_code_editor_includes()` once per request (the facade script and `PgCodeEditor.configure({ bundle, phrases })`); the engine bundle (~600 KB) is fetched on the first editor only. The engine's texts come from `pg_code_editor_phrases()` (`lang()`, the keys `_sdCodePhrases()` uses in the designer); the inline JSON is `pg_code_editor_json()` (`JSON_HEX_TAG`).
- F11 fills the window with the editor (`.pg-code-field-full`, `body.pg-code-field-open`), Esc leaves. The instance is kept in `window.pgCodeEditors[id]`; a screen that changes the language after a file name calls `pgCodeEditors.code.setLanguage()`.
- The field's panel look is `.pg-code-field` in `backend.src.css` (border and radius like a form control, 12rem minimum, 80vh maximum); the designer's panes and the code dialog carry only `.pg-code-editor` and are not touched by it.

## What does 'code_editor' => false do, and when is it set?
- `pg_page_shell()` / `output_header()` with `'code_editor' => false` leaves CodeMirror 5 and its linters (40 files, ~2 MB) out of the head and parks the tags in `<template id="pg-code-editor-assets">`; `window.pgCodeEditorReady(markup, done)` (`backend.src.js`) loads them when markup that mentions CodeMirror arrives later (a Site Settings pane with a code field). A screen whose code fields are the facade's sets it.
- Moved: `edit_file.php` and the screens whose only use was `get_codemirror_javascript()` (`add_/edit_custom_style`, `_dynamic_region`, `_designer_region`, `_login_region`, `_field`, `_product_group`, `edit_javascript`, `edit_theme_css`, `editor_edit_file`, `edit_form_*_view`, `view_system_style_source`, the product screen of `product_builder.php`). A `height` in the call is honoured now (CM5 ignored it). A plain-text type (`plain`, `text/plain`, …) turns the HTML lint off (`pg_code_editor_is_plain()`).
- The File Manager's file window (`view_folders.php`) builds its editor itself: `loadAssets('code_editor')` appends `pg_code_editor_includes()`, `PgCodeEditor.load()` runs before the window opens, `PgCodeEditor.create()` in a host after the hidden textarea, `destroy()` on close; the language comes from the server (`pg_explorer_editor_language()`: css, javascript, json, html, or `text` = HTML colours, no lint).
- Still on CodeMirror 5: the settings panes (`includes/settings/*.php`, drawn into the dialog by AJAX), `create_file.php` (switches the mode after the file name: `pgCodeEditors.code.setLanguage()`), `page_designer.js`, `theme_designer.php`, `backups.php`, `smtp_settings.php`, `generate_layout.php`. When the last one has moved, `get_codemirror_includes()`, the template, `pgCodeEditorReady()` and `assets/lib/codemirror/` go.

## How does the colour scheme reach the editors?
- The server reads the `prefers-color-scheme` cookie (`pg_code_editor_theme()`) for the first paint; the panel's scheme switch (`setTheme()` in `backend.src.js`) pushes `dark`/`light` to every open CodeMirror 5 instance and, through `window.pgCodeEditors`, to every facade editor (`editor.setTheme()`), so a switch needs no reload.
