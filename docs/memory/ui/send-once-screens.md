## Which screens send once for longer than 3 s?
- The common pattern: a `window` submit listener lets the first submit of the form through and cancels any later one until a page restored from the cache (`pageshow` with `persisted`) resets it, sets `aria-busy` on the form and fills a `role=status` `aria-live=polite` line. The submit button is never disabled, so its value travels. A type=button Ajax action disables itself instead (`button-busy-state.md`).
- The barcode stock screens (barcode_increase/decrease_inventory.php): `#barcode_read_button` is disabled while its Read request runs (`complete` enables it); a scan is never held, a repeated scan is a real second unit. A success also fills the visually hidden `#barcode_status` (role=status) with the product and its new quantity. Before (PR #3167) a double click with quantity 5 moved the stock by 6.
- The order screen's card refund dialog (view_order.php): the common listener, `aria-busy` on the dialog and `#payment-refund-status`. The server takes `GET_LOCK(pg_payment_refund_lock_name($order_id), 0)` and turns a second request away; before, a slow provider answer let a second click refund twice.
- Orders > Export for Paraşüt Selected (view_orders.php): Confirm sends the form with `fetch` (`pgParasutOrderExport()` in backend.src.js, to the form's `action` attribute: the hidden `action` input shadows `form.action`), saves the zip under its `Content-Disposition` name, then reloads. A `role=status` overlay shows the wait (`data-wait-text`); an answer that is not a zip removes it and shows a danger toast (`data-error-text`). Before (PR #3348) the page reloaded after a fixed 4 s, which cancelled a slower export after edit_orders.php had already marked its orders exported: no zip, no notice.
- The ERP account CSV import's mapping step (erp_accounts_import.php): the same `window` submit listener on `#erp_import_map_form`; Start import sets `aria-busy` on the form and fills `#erp_import_map_status` with "Importing…". Before, a second press after 3 s ended on "The upload has expired." and hid the counts.
- Import My Site's Import (import_design.php, scan-result page only; Scan streams and is left alone): the same listener on `#import_design_form`, `aria-busy` and "Importing…" in `#import_design_status`. Before, a second press ended on "could not find any items to import" although the pages were written, and scanning again made a second copy.
- Import ZIP (import_zip.php, `#import_zip_form`) and the File Manager's Import ZIP and Import ZIP for the Visual Page Editor dialogs (view_folders.php, `#import_zip_form` / `#import_design_zip_form`): the same listener, `aria-busy` and "Importing…" in the form's `…_status` line. Before, a press after 3 s imported the archive again: a second timestamped folder with new pages and files, or a second design.
- The File Manager's "Save a copy as PNG/JPG/WEBP" on an SVG (view_folders.php `rasterizeSvg()`): a module-level `rasterizing` flag turns a press away while a conversion runs, and the three `[data-file-tool="rasterize"]` buttons are disabled meanwhile (labels unchanged) and enabled again on every outcome. Before, a double click on these type=button buttons saved two copies (each run uploads a new file through `explorer_upload`).
- ERP Send the e-mail (edit_erp_invoice/quote/purchase_order.php): `mail_form` carries `data-erp-send-once` with the erp_bank_statement.php listener and a `data-erp-send-once-status` line ("Working on it. Wait for the answer before leaving this page."). The PDF (dompdf, or the provider's copy on an invoice's first official send) and `email()` (not queued) run in the request; before, a press after 3 s mailed the document twice and wrote a second history row.
