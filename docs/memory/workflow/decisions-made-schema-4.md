## Which schema was approved on 2026-10-29 (continued)?
- Flow templates G3 (#3120, architect, the next free Workspace label when pushed): `ws_flow_templates` by `install_create_table()`, in `get_tables()`: `template_key` VARCHAR(40) UNIQUE (`site_<id>`, never a built-in key), `category` VARCHAR(16), `title` VARCHAR(160), `help` VARCHAR(255), `icon` VARCHAR(40), `graph` MEDIUMTEXT (the normalized draft graph), `settings` TEXT (JSON in the built-ins' shape), `source_flow_id`, `created_by`, `updated_by`, `created_at`, `updated_at`, `binned_at` (the `ws_flows` conventions). Saved from a draft the person may edit; channel, person, time, url and address values become settings with the current values as defaults; secrets in box configs are dropped; `boxes`, `threads` and `motion` are computed on read. Listed to everyone who builds flows under "Saved on this site"; title, help and category edited and the row deleted by its creator or Manager and above; Use goes through the built-ins' setup and publish checks; erasure re-points or zeroes `created_by` / `updated_by` as for flows; G4 reads and writes the same row.
- CRM seams 9 (#3138, architect, the next free Workspace label when pushed; 11.0.116 today, 115 held by #3146): `ws_refs.source_type` ENUM('message','task') to `VARCHAR(20) NOT NULL DEFAULT 'message'` by `install_modify_column()` behind `install_column_info()` (only while the type is an enum, so a rerun skips); values and `idx_source` stay, the table is copied once, no `install_heavy_tables()` entry (one narrow row per tag). New sources `note` and `wtable_row` with `channel_id` 0; the writers stay off until a probe sees the VARCHAR (a `'note'` row on the ENUM would be stored as `''`); `ws_ref_sources()` leaves unknown sources out. Readers list a note only where `ws_note_access()` allows and a row only where `ws_wtable_access()` reaches its table (Claude's key through `ws_api_note_reachable()` / `ws_api_wtable_reachable()`). Older notes and rows are indexed by a re-runnable backfill in the cron dispatcher under a time budget, cursor in `config_text`, no further schema. Refused: appending to the ENUM (every later source a MODIFY) and a LIKE scan on every record screen.
- Return label on the returns screen (#3178, architect, the next free general label when pushed; 11.0.126 today): `shipment_labels.order_return_id INT UNSIGNED NOT NULL DEFAULT 0` by `install_add_column()` and `KEY idx_shipment_label_return (order_return_id)` by `install_add_index()`; existing rows keep 0 (order-screen labels, their per-address rule unchanged). A label made from a request carries its id: the one-active-return-label check is per request for such rows, the paid call runs once per request (a second press, a repeated form or a bulk run finds the active label), and a second request on the same address is not refused.
