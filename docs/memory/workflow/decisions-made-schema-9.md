## Which columns were approved?
- Returns changed-since (#5927, architect, step X2b of `plans/external-api-coverage.md`): `order_returns.updated_at` INT UNSIGNED NOT NULL DEFAULT 0 with an index on (`updated_at`, `id`), in the next free 2026.11.0 sub-step at landing; backfilled once with GREATEST of the six status stamps; every writer of the row sets it through one helper; `GET /returns?modified_since` pages on it, oldest change first, like `GET /orders`. Reason: `api/api-endpoint-rules.md` allows a since filter only on a stamp every writer moves; a refused refund and a new return label move no stamp.
- Designer form fee (#6129, architect; feature in `designer/custom-form-logic.md`): `custom_form_pages.payment` TEXT NULL (the setting as JSON in the `pg_form_fee_settings_clean()` shape; NULL or '' = no fee, read and written beside the form's other settings), `forms.order_id` INT UNSIGNED NOT NULL DEFAULT 0 with INDEX idx_order_id (order_id), `forms.paid_at` INT UNSIGNED NOT NULL DEFAULT 0 (0 = unpaid; the badge, the Unpaid filter, the system field and the API's read-only `paid` derive from it; set once from `pg_order_complete()`), in the next free 2026.11.0 sub-step at landing; the record points at the order, the order carries nothing, as a subscription points at its renewal order. Reason: "no schema" in #5035 meant no `form_payments` table; `form_data.order_id` means the billing data of an order (read by the order screen, the prefill and the privacy export, deleted with the order), and a widget's `system_region_config` belongs to the placement, not the form.
- Appointment bookings slot key (#6135, architect, BK1 of the appointment booking plan, `commerce/bookings-decisions.md`, PR #6137): `bookings.slot_at` INT UNSIGNED NULL, a copy of `start_at` on a live row and NULL on a cancelled one, with UNIQUE idx_staff_slot (staff_id, slot_at) in place of idx_staff_start (NULLs never collide, as `sms_outbox.reference`); `idx_start` stays. Changed in the CREATE TABLE while BK1 is open, else a BK3 sub-step adds the column, backfills live rows, adds the key and drops the old index (an unreleased table with no rows). Reason: #5032 keeps cancelled rows 400 days, so the (staff, start) key refused a new booking at a cancelled start; a VARCHAR slot key or an archive table were not chosen.
- Content importers, disabled users (#6186, architect, WordPress import, `platform/import-wordpress.md`, PR #6185): `user.user_disabled_at` INT UNSIGNED NOT NULL DEFAULT 0 (0 = enabled, else when it was disabled; the `user_created` stamp shape) and `import_items.kind` widened with `'user'` (the `$widen` shape of 2026.11.0: `install_column_info()`, then `install_modify_column()`), in the next free 2026.11.0 sub-step at landing. Every path that turns a credential into a `user` row treats a disabled row as no match: `validate_user()` beside its deleted-account branch, password and API password sign-in, forgot and reset password, provider sign-in by id and by address, passkeys and MFA, `login_as_user.php`, `includes/api/auth.php`; the user screen gets an "Account enabled" switch (not one's own account, not the last enabled administrator). The importer creates an author disabled through `create_member_user()`, skips an address an existing user holds and records a `user` item; undo removes it only while still disabled and credential-free. Reason: `user_password_algo = 3` means an external account, not a disabled one, and the reset flow or a provider's address match would sign such a user in (#5034 question 2 said no sign-in).
