name: pr-footer-and-trailers
description: Where the "Generated by Claude Code" footer and commit trailers come from, the settings that turn them off, how to write without it, and why only the merging session removes it.
---

## Does the session that opens a PR remove the footer?
- No. The session that merges PRs (the coordinating session in `pr-backlog-coordination.md`) cleans PR bodies and comments and writes the squash title and message before it merges (owner, 2026-10-24).
- Other sessions write their body or comment once and do not retry, re-edit or chase a footer GitHub adds to it.
- Commit messages and code comments stay the author's job: no trailers, no AI or process traces (CLAUDE.md rule 2).

## Where does the "Generated by Claude Code" footer come from?
- A cloud session's GitHub proxy appends `---` / `_Generated by [Claude Code](…)_` (with or without the session link) to every PR or issue body and every comment written through `gh api` (`pulls/<n>`, `issues/<n>`, `issues/<n>/comments`). Claude Code also asks for `Co-Authored-By:` / `Claude-Session:` commit trailers. `.claude/settings.json` turns all of it off: `attribution.commit` and `attribution.pr` empty, `attribution.sessionUrl` false.
- A cloud session reads that file only when it starts inside the clone of its one repository; so does a thread of a Projects project with one repository. A session with several repositories, or one whose repository was added after it started, does not: for the organisation account the same `attribution` block sits in the server-managed settings, next to `channelsEnabled` (claude.ai › Organization settings › Claude Code › Managed settings, Owner role). Footers keep appearing anyway, so a session cannot count on either.

## How is a body written without the footer?
- Through the GitHub MCP tools, not `gh api` (tested 2026-10-23 on #1316, #1322, #1352, #1383, #1384, #1425):
  - PR body: `mcp__github__update_pull_request` with the full body keeps it exactly as given. `mcp__github__create_pull_request` still adds the footer, with the session link; one `update_pull_request` with the same body removes it (tested on #1428).
  - Issue body: `mcp__github__issue_write` (`create` or `update`) keeps it as given.
- Do not edit a clean body with `gh api` afterwards: the footer comes back.

## And a comment?
- `mcp__github__add_issue_comment` still gets the footer. `mcp__github__update_issue_comment` with the same text stores it clean (tested on #1370 and #1322).

## And the commits that reach development?
- A squash merge with a hand-written title and message is clean through both `mcp__github__merge_pull_request` and `gh api -X PUT …/pulls/<n>/merge`; the author is the account's (`Erdal Güral`). Branch commits do not reach `development` after a squash; they are still written without trailers (CLAUDE.md rule 2).

## Who removes a footer that is already there?
- The session that merges the PR, before merging: it sends the body again through `update_pull_request` without the last two lines and each footed comment through `update_issue_comment` (owner requests 2026-10-23 and 2026-10-24: sessions were stalling on the footers). Any other session may do it, but need not.
- A session linked to the owner's computer can also do it in the Claude app's built-in browser, signed in to GitHub as the owner: PR › description `⋯` › Edit, delete the last two lines, Update comment.
