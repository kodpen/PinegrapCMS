## Which tables and columns were approved?
- Bundle back order choice (owner, 2026-11-09, #8365; bug #7746): `products.bundle_backorder` TINYINT(1) NOT NULL DEFAULT 0, step 11.0.176, filled once from `backorder` for `bundle = 1` rows. The product builder saves a bundle's Backorder tick there; `products.backorder` stays a cache, `bundle_backorder && backorder_allowed`. Why: it keeps the merchant's control and makes the cache reversible. A bundle already stuck at 0 stays 0 until saved once. Chosen over a fully derived switch (the merchant could not refuse back orders) and a hint only (the bug stays).
- Workflow table bin (owner, 2026-11-09: approved in principle, a deleted table or row comes back within the Recycle Bin's days; the columns shaped in the architect's absence, as the owner allowed; built in #8412, `workspace/workflow-tables-bin.md`): `ws_wtables.deleted_at` and `deleted_by` INT UNSIGNED NOT NULL DEFAULT 0 by `install_add_column()`; `ws_wtable_row_bin` by `install_create_table()`: `id`, then the row as it was (`row_id`, `table_id`, `position`, `cells` MEDIUMTEXT, `revision`, `created_by`, `created_at`, `updated_by`, `updated_at`), `links` MEDIUMTEXT NULL (JSON: its `ws_refs`, and the cells that linked to it once rows link), `deleted_by`, `deleted_at`; KEY (`table_id`, `deleted_at`), KEY (`deleted_at`). Why: the 13 statements that read `ws_wtable_rows` stay untouched, and a marked table keeps its id for the flows that name it. Refused: `deleted_at` on the rows (every reader would need the filter) and the panel's `recycle_bin` (site-wide, no per-table rights).
- Team replies right (owner, 2026-11-09; the slice #3075 left open, `decisions-made-schema-3.md`): `user.manage_workspace_replies` TINYINT UNSIGNED NOT NULL DEFAULT 0 by `install_add_column()`, read behind a probe of its own. Team rows are `ws_saved_replies` rows with `scope` `team` and `user_id` 0, so the table does not change. Built in #8405 (step 11.0.179, `workspace/workspace-saved-replies-team.md`).
- Agent token counts and limit (owner, 2026-11-10, all three columns; `workspace/agent-activity.md`, `workspace/agent-token-limit.md`): `ws_ai_requests.tokens_in` and `tokens_out` INT UNSIGNED NOT NULL DEFAULT 0, the tokens of a request summed over its steps from each answer's `usage`; `ws_agents.token_limit` INT UNSIGNED NOT NULL DEFAULT 0, a model assistant's tokens for a calendar month, 0 for none; all by `install_add_column()`. Why: a model assistant spends the site's own provider key and nothing counted it, and the hourly brake alone lets one agent wake some 21,600 times a month.
