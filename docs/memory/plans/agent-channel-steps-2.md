## Which steps are there?
- Sizes and rules as in `agent-channel-steps.md`.

- A5 (M, schema) done in #8187. Channel memory and decision marks. Entries (title, text, tags, author, pinned, expiry) in every channel, agent channel or not (#8188); read as Claude Code reads memory: the brief carries the index (id, title, tags; pinned first, expired left out), the agent reads only the entries it needs (`workspace.memory.get`); a Memory tab where the channel has an agent, else only a button in the channel's settings (owner 2026-11-08, `workflow/decisions-made-workspace-9.md`); a decision mark on a message by any member, an agent too (`ws_messages.marked_by_kind`), and its decision line in the brief; routes `workspace.messages.mark` and `workspace.memory.list|get|create|update|delete`, MCP tools too. What landed: `workspace/channel-memory.md`. From here a message of the owner's account marked as a decision is an owner decision (`workflow/architect.md`).
- A5b (S) Agents ask the people. After A5. Approvals and polls opened to agent keys as the owner's questions (an agent asks the people with a poll or an approval, the recommended option first), the outcome as a decision line in the brief. Start from `ws_api_person_only()` / `ws_api_own_words_only()` on the poll and approval routes (`workspace/workspace-api-callers.md`): an agent opens one, only people answer.
- A6 (M) Model assistants. After A3. A card each: handle (`@chatgpt`), name, avatar, sealed key, model, test; OpenAI-compatible chat APIs (OpenAI, Gemini, Mistral, DeepSeek, OpenRouter, Azure OpenAI, a custom address such as Ollama) answered by `ws_ai_step()` with that address, key and model: the same tools, proposals and approvals; `ws_ai_requests.agent` `model:<id>`; each provider's API and data terms rechecked first; the question names the provider.
- A7 (M) Risk tiers. After A4. Tiers on `ws_change_types()` (1 reading and messages, 2 a reversible record change, 3 irreversible), the execution policy from the channel-agent row, an undo journal for agent changes; then flows: an "ask an agent" box and agent-started runs by permission (`plans/flows-next.md` shape).
- A8 (M) Further doors. After A4. The Claude Code channel plugin in a separate repository (`kodpen/pinegrap-claude-channel`: poll, claim, push the event, tools reply, fail, context, record, react, post), applied to Anthropic's channel list, under the shelved plan's security rules; per-person sessions over OAuth with the "via" badge; a chat box on the dashboard on the same catalogue.
- A9 (S) The canvas as an agent tool. After A4. `workspace.canvas.create` and `workspace.canvas.update`: the image editor's canvas document (`pg_image_editor_canvas_is_doc()`) with the PNG the agent rendered, kept as `workspace_file_save.php` keeps a canvas (the PNG as the message's or note's file, the document beside it in `file_versions`), so people open its layers in the editor; over MCP under the 1 MB rule (`api/workspace-mcp-small-file.md`); the PNG rendered by the server instead once `plans/image-editor-server.md` lands. Workflow tables need nothing: their routes are complete (`workspace/workflow-tables-api.md`).
