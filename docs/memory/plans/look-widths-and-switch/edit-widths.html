Add and edit screens at 1700 px: how do the cards use the 1300 px form column?

Owner decision #9070: centred, at most 1700 px; status column 376, gap 24, the form column the rest (1300 px). A field is as wide as its content asks; an input never runs the width of its column. Plan step LW2, PR #9269, question #9271. Window 1920 px; click a picture for its full size.

  • A — the measure alone. Fields stay on today's 12-column grid and stretch with the column: a full-row input is about 1270 px, a half-row one about 630.
  • B — two cards abreast in the form column, fields as today. Cards flow down the left column, then the right, so the order on screen follows the cards' heights.
  • C — one card per row; inside it a full-row field takes half the row and an input is at most about 480 px; text areas, editors and tables keep the card's width. Card order stays, each card is shorter. (Recommended.)

The pictures of B and C are drawn with a stylesheet laid over the real screens, so a few rows sit unevenly (the settings rows above all); the chosen way is built properly per screen.
