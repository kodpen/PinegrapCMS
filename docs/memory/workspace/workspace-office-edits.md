## How does a workbook or a document of a conversation get edited?
- The preview window (`previewFile()` in `workspace.js`) asks `ws_file_office` with `edit: 1` for an .xlsx/.xltx or .docx/.dotx; only these are edited. It asks for .xlsm/.xltm/.docm/.dotm too (`OFFICE_EDIT_NAME`), but a macro form posted before channels refused them (`workspace-upload-refusals.md`, PR #TBD) comes back as the plain preview, since its edited copy would be refused, and `ws_file_edit_target()` refuses its save. For someone who may write in the channel (`ws_can_post_channel()`) the answer carries the edit information of the file window (docs/memory/platform/office-cell-edits.md, docs/memory/platform/office-paragraph-edits.md) and `can_replace` / `can_send`, as the text window's `ws_file_text` does; a reader gets the plain preview.
- The grid or the document is the file window's (`pg_office_view.js`, `view.kind` xlsx or docx); a footer under it says what Save does and holds the button, which stays off until something changed (typing counts; Ctrl+S in the view presses it). Closing the window with changes asks first (`file_cells_unsaved`, `file_paragraphs_unsaved`).
- `ws_file_office_save` (message_id, `cells` or `paragraphs` by the file's kind, office_version, as): `ws_file_edit_target()` with kind `office` (a workbook or a document), then `ws_file_office_edited()` copies the message's file into data/temp, writes the changes into the copy with `pg_office_xlsx_save()` or `pg_office_docx_save()` (same locks, same version check: a file replaced meanwhile is refused) and hands back its bytes. The file the message carries is never written to.
- Then the text file's path: `as: replace` (the poster, `ws_file_can_replace()`) puts the new file in place, the old one listed in `ws_file_edits` as an earlier version; otherwise `ws_message_file_send()` posts the edited copy as the person's message in reply. Both go through the upload checks (`ws_upload_inspect()`, 20 MB). The callers pass `fileEdited()`, which redraws the message or syncs the conversation.

## What was checked?
- Sandbox with Playwright, workbook and document: the poster saved over their file (message on the new file id, history row old → new, earlier file untouched); a second staff user got "Send the edited copy", and Ctrl+S posted a reply carrying the copy while the poster's message kept its file; closing with a change asked first; Save woke up while typing.
